# 15 — Internationalization

## Locales (v1.0 set)
| Locale | BCP-47 | Notes |
|---|---|---|
| English (US) | `en` | default, source strings |
| Urdu | `ur` | **RTL**, Nastaliq-friendly font fallback |
| Arabic | `ar` | **RTL** |
| Spanish | `es` | Latin + LatAm variants via `es-419` |
| Chinese (Simplified) | `zh-Hans` | |
| Hindi | `hi` | Devanagari |

## Strategy
- **GUI**: `svelte-i18n`, JSON catalogs in `host/gui/src/i18n/`;
  RTL via `dir="auto"` on layout + SvelteKit-independent flip classes.
- **Android**: standard `res/values-ur/`, `values-ar/`, etc.
  (present in scaffold). No hard-coded strings in Kotlin.
- **CLI**: gettext-style via `rust-i18n` with fallback to English;
  `--lang` flag + `LANG` env.
- **Protocol**: none. All wire text is UTF-8; channel semantics are
  locale-independent by design.

## Process
- Strings extracted weekly (`npm run i18n:extract`).
- Community translation PRs: per-locale reviewers named in
  `host/gui/src/i18n/OWNERS` (from the beta program, Phase 3).
- RTL pass: a dedicated layout review with `dir=rtl` forced in CI
  (screenshot diff on 3 key screens).
- Voice/brand: product name stays "UniTether" in all locales
  (no transliteration); UI strings localized.

## Quality gates
- Coverage: 100 % of keys translated before a locale ships
  (missing key = English fallback + CI warning).
- Length budget: Arabic/Urdu ~15–20 % longer; UI uses elastic
  layouts (no fixed-width labels).
- Test: `npm run i18n:check` (untranslated/unused key detection).
